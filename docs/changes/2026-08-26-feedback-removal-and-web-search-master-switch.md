# 移除建议功能与联网搜索总开关

日期：2026-08-26
目标版本：1.12.5

## 结论

现有 `webSearchEnabled` 已存在于设置结构和界面中，但尚未成为搜索主链的硬授权边界。关闭时，专业/政策/高风险问题的预搜索仍可执行，未配置 Tavily 时仍会访问百科站点，而且模型始终能看到并调用 `web_search` 工具。因此当前实现只能达到 `LEVEL_2_RECORDED`（开关被保存并显示），不能证明它对最终执行具有因果作用。

本次把开关提升为端到端硬门控：关闭时，搜索判断模型、强制专业审查、Tavily、百科备用检索、原网页读取、模型主动 `web_search` 以及失败后的百科人工检索链接全部禁用；回答继续依据文档、选区、附近上下文、Tip 记忆和模型已有知识生成，并明确标记外部事实未联网核验。开启时保留原有 Tavily/百科降级与可靠性审查路径。

同时按产品要求完整移除“修改建议箱”，包括 UI、前端 API、服务端路由、中继环境变量、样式、测试和文档，不保留隐藏或可直接调用的旧入口。

## 设计不变量

1. `webSearchEnabled === false` 是硬授权边界，不是提供商偏好。
2. 关闭时 Tavily Key 即使已保存也不得触发 Tavily 请求。
3. 关闭时未配置 Tavily Key也不得触发百科、参考站点或原网页读取。
4. 关闭时模型请求中不得出现 `web_search` 工具定义，执行器仍必须防御伪造/陈旧工具调用。
5. 关闭时不调用 AI 联网判断分类器；专业程度判断仍保留，因为它不访问网页，并继续用于风险提示。
6. 关闭时专业、政策和高风险问题仍需给出有效回答；外部事实标记为未联网核验，并保留必要的人工专业复核提示。
7. 开启时才允许 AI 判断是否需要联网；有 Tavily Key 使用 Tavily，无 Key 才使用有限中外参考站点。
8. 关闭与开启的反事实运行必须改变真实网络动作，而不仅改变 trace、置信度或提示文案。
9. 新用户和没有历史设置的本地用户默认关闭；已有用户显式保存的开启状态不做破坏性迁移。
10. 建议箱的前端元素、前端方法、HTTP 路由和中继配置必须全部不存在。

## 非目标

- 不删除 Tavily 或百科搜索能力；它们在用户显式开启联网后继续可用。
- 不关闭 Python、单位检查、符号计算等纯本地工具。
- 不删除专业程度评估或高风险人工复核提示。
- 不清除用户已经保存的 Tavily Key。
- 不把“关闭联网”伪装成“搜索失败”，也不自动重新打开开关。

## 先行回归与负向测试

1. 默认设置读取必须返回 `webSearchEnabled: false`。
2. 已保存 Tavily Key但关闭开关，专业政策问题不得增加 Tavily、百科或外部 fetch 请求。
3. 同一关闭场景不得调用联网判断模型，不得向回答模型暴露 `web_search` 工具。
4. 关闭场景必须返回非空答案；不得包含百科 URL、Tavily 质量提示或“联网审查未通过”的错误结论。
5. 关闭场景必须产生“联网搜索已关闭”记录，专业问题则显示联网审查未执行且外部事实未核验。
6. 将开关改为开启后，同类专业问题必须真实触发搜索，作为反事实因果证明。
7. 无 Key 但开启时仍走有限参考站点；有 Key 且开启时仍走 Tavily。
8. `/api/feedback` 在鉴权与未鉴权场景均应返回 404，且中继请求计数保持为零。
9. 桌面设置中不得出现 `.feedback-box`、“修改建议箱”或 “Suggestion box”。
10. 搜索关闭后 Python 工具仍可执行，证明本次门控没有误伤本地工具。

## 验收条件

- COMPONENT_CAPABILITY：设置可保存并读取开关；研究与技能执行函数具备关闭保护；建议路由不存在。
- FORMAL_PATH_INTEGRATION：正式 Tip chat 入口读取当前用户设置，并据此跳过联网判断/预搜索、移除工具定义、阻断执行器绕过、调整审查与最终输出。
- INDEPENDENT_EVALUATION：集成测试通过真实 HTTP Tip chat、可注入外部 fetch 和模型请求体观测，证明关闭与开启会改变真实网络动作。
- 只有在关闭反事实网络请求为零、开启反事实真实产生请求、答案仍非空、完整测试与桌面烟测均通过后，才允许标记 `LEVEL_5_PREDICTION_BEARING`。
- 若只能证明字段存在或 trace 文案变化，标记 `NOT_CAUSALLY_VERIFIED`，不得发布。

## 本轮新鲜验收证据

- 先行红测：旧实现运行 `test-product-behavior.mjs` 时，关闭参数仍得到 `required: true / mandatory-safety`，证明测试能捕获旧绕过路径。
- `pnpm skills:test`：完整通过。关闭场景中 Tavily 请求、5 个参考站点请求和可注入外部 fetch 的增量均为 0；联网判断模型调用增量为 0；回答模型工具定义中不存在 `web_search`；最终回答非空且不含百科 URL、Tavily 提示或“联网审查未通过”。
- 同一集成运行把开关重新设为开启后，专业/政策问题产生真实搜索请求并把来源进入最终回答，证明开关改变实际 action 和 prediction lineage，而不仅改变 trace 文案。
- 本地模型集成测试显式开启联网后仍能通过有限中外参考站点取得证据；关闭默认值不再被旧测试隐式绕过。
- 鉴权与未鉴权 `POST /api/feedback` 均返回 404；前端 API、设置 UI、中继环境变量和当前 README 配置均已移除。
- `pnpm desktop:smoke` 与打包后 `release/win-unpacked/AI Tip.exe --smoke-test` 均通过；结果包含 `feedbackRemoved: true` 与 `webSearchDefaultOff: true`，并继续覆盖文档导入/保存、DOCX 表格、PDF/OCR Tip、递归 Tip、本地模型和登录。

因此本轮联网总开关达到 `LEVEL_5_PREDICTION_BEARING`：正式 Tip chat 入口消费开关，关闭会删除搜索计划与工具能力、阻止真实外部请求并改变最终回答的核验状态；开启会恢复真实搜索和来源依赖。建议功能移除达到正式路径不可调用状态。Windows 1.12.5 包已经生成，但当前安装包没有 Authenticode 签名；这不影响上述功能因果验证，但会影响 Windows 下载信誉提示，发布前仍需代码签名证书。
