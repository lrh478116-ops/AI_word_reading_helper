# 非阻断专业审查与完整回答显示

## 审计结论

截图中的两个问题来自两条不同但相关的数据链。

第一条是正式聊天链中的覆盖式阻断：模型已经生成 `answer`，引用审计判定为 `UNSUPPORTED` 后，服务端在 `server/index.ts` 直接把 `answer` 重新赋值为“不会展示原回答”。专业度分类失败、专业问题缺少搜索配置以及高风险交叉验证不足也存在同类提前阻断或覆盖。审查结果因此不只是影响置信度或标签，而是删除了已生成的用户可见内容。

第二条是 Tip 悬浮预览链：最终回答完整保存在 `TipMessage.content`，但 `TipThread.summary` 被固定截为 120 字；文档 Tip 按钮的原生 `title` 又只读取 `summary || title`。所以悬浮框必然在第 120 字附近中断。这不是聊天正文 CSS 的视觉裁剪，而是预览读取了错误的短摘要字段。

此外，所有 Chat Completions 调用都没有处理 `finish_reason = "length"`。模型若因服务端输出长度上限停止，当前代码会把不完整结果当作正式完成并持久化。这是另一条真实的半截回答风险，不能只修悬浮框。

## 已确认问题

| 问题 | 严重程度 | 正式位置 | 当前行为 | 因果影响 | 统一修复方向 | 阻止发布 |
| --- | --- | --- | --- | --- | --- | --- |
| 审查失败覆盖原回答 | 高 | `server/index.ts` 专业引用审查尾部 | `answer` 被替换为拒绝文字 | 已生成内容不进入 SSE、数据库和 UI | 保留原回答，追加明确审查警告；trace 标记 warning | 是 |
| 专业度分类失败直接阻断 | 高 | 聊天入口的 `assessmentError` 分支 | 不执行正常回答 | 分类组件故障使聊天失语 | 使用规则评估作为可追溯降级，继续回答并标记评估未完成 | 是 |
| 缺少联网配置即阻断专业回答 | 高 | `reviewRequired && !reviewSearchReady` | 只显示配置提示 | 用户无法获得任何解释 | 继续生成一般性回答，明确“未联网核验”，禁止伪装为已验证 | 是 |
| 高风险交叉验证不足覆盖回答 | 高 | `highRiskKind && finalProduced` | 原回答被删除 | 即使已有教育性内容也不可见 | 保留回答，追加高风险人工复核提示 | 是 |
| Tip 预览只读取 120 字摘要 | 高 | `TipThread.summary` → 原生 `title` | 悬浮框在句中中断 | 完整消息存在但无法从 Tip 入口预览 | 预览直接读取第一条 assistant message；summary 仅用于记忆和列表 | 是 |
| 模型长度停止未续写 | 高 | 所有最终 Chat Completions 调用 | `finish_reason=length` 被当作完成 | 数据库存入真实半截回答 | 有界自动续写，将续写请求绑定前文，直到 stop 或达到明确安全上限 | 是 |
| 引用审计只审前 12,000 字符 | 中 | citation audit 输入 | 长回答尾部没有被审计 | “通过”可能仅代表开头 | 分块审计全部回答；任一块失败则整体 warning | 是 |

## 设计不变量

- 审查层不能删除、覆盖或隐藏已经生成的回答正文。
- 审查通过时显示通过状态；未通过、未完成或缺少联网条件时显示清楚的风险警告，但回答仍可阅读和复制。
- “未联网核验”不得伪装成“权威审查通过”；trace 与正文提示必须和真实证据状态一致。
- 高风险问题仍追加非个性化、需专业人员复核的提示，但不让整个聊天失语。
- Tip 完整预览必须来自第一条 assistant `message.content`，不能来自 120 字 summary；后续追问不能改变悬浮预览的基准回答。
- 完整预览允许在视口内滚动，但不得丢字符；正文、复制结果、数据库和预览的首尾签名必须一致。
- `finish_reason=length` 必须触发续写；续写必须把已生成回答作为 assistant 历史输入，并明确要求从中断处继续、不得重复。
- 自动续写必须有有界轮数，避免异常提供方永远返回 length；达到边界时要追加“提供方仍截断”的明确说明，不能静默声称完整。
- 普通问题不新增 Tavily 请求；专业问题的搜索预算策略继续生效。
- summary 仍可保持短摘要用途，但不得再承担完整内容展示职责。

## 非目标

- 不把审查失败改成“审查通过”。
- 不取消来源、权威性、引用结构、置信度和高风险提示。
- 不承诺突破模型提供方的上下文窗口；在提供方持续截断时明确告知，而不是无限请求。
- 不移除 Tip 点击打开完整聊天的既有行为。

## 先失败的回归与反事实测试

1. mock 模型先生成包含 `UNSUPPORTED_CLAIM` 的专业回答，再让审计器返回 UNSUPPORTED：最终持久化消息必须保留原回答，并追加审查警告。
2. 专业度分类器返回非法结构：规则评估 trace 必须标记评估未完成，但正式回答仍产生；不得无搜索消费普通问题额度。
3. 高风险证据不足：回答正文仍存在，同时附带人工复核警告；不能只剩“不会给出”。
4. mock 第一次最终回答返回 `finish_reason=length` 和唯一前半段，第二次返回 `stop` 和唯一后半段：SSE、数据库和重新打开结果必须按顺序包含首尾签名且只出现一次。
5. 创建长度超过 120 字的第一条回答，再产生内容不同的第二轮回答；收回 Tip 后悬浮 marker：自定义预览必须完整等于第一条回答、包含其尾部签名、不等于第二条回答，且 marker 不再使用 summary 原生 title。
6. PDF Tip、普通文档 Tip 与表格 Tip 均复用完整预览组件；点击仍打开对应 Tip。
7. 任一引用审计分块失败时整体 professional review 为 warning，不得删除回答。

## 验收等级

只有“模型生成原文 → 审查失败 → 原文仍进入 SSE → 完整内容持久化 → Tip 收回 → marker 预览显示首尾 → 点击重新打开仍是同一消息”在 Windows 源码态和打包态均通过，才能判定 `LEVEL_5_PREDICTION_BEARING`。单独检查字符串或 CSS 只能证明组件能力。

## 实施与新鲜证据

- 正式聊天入口不再因专业度模型解析失败、缺少联网配置、证据门槛不足或引用审计未通过而删除回答；这些状态以 warning trace 和正文警告呈现。
- `finish_reason=length` 已进入正式模型调用链，最多执行 3 次有上下文的连续续写；持续截断时明确显示提供方限制。
- 引用审计覆盖完整回答的全部 12,000 字符分块，不再只审查开头。
- 普通文档、Word 表格、聊天子 Tip 与 PDF Tip 的 marker 统一读取第一条 assistant 消息全文；第二轮及以后回答不会替换悬浮预览。
- PDF marker 打开 Tip 时以内容坐标补偿阅读区异步重排；桌面烟测记录的最大锚点/栏位位移为约 `0.05px`，低于 `2px` 门槛。
- `pnpm typecheck` 通过。
- `node scripts/test-skills-integration.mjs` 通过，包含审查失败保留原回答、评估失败继续回答、长度截断续写和无发布者 API 旁路的负向检查。
- `pnpm desktop:smoke` 通过，包含同一 Tip 两轮不同回答后悬浮预览仍严格等于第一轮全文的反事实检查。
- `pnpm skills:test` 完整回归通过。
