# 专业问题联网审查与设置建议箱

## 已确认问题

1. 现有系统只识别少量医学、法律、金融高风险词和时效关键词，没有通用的专业程度评估。
2. 非高风险专业问题不会强制联网，模型可以绕过搜索直接回答。
3. 现有引用审计发生在部分回答已经流式发送之后；审计失败只记录 warning，不改变已展示或持久化的回答。
4. 设置中没有建议提交入口，服务端也没有建议投递 API。
5. 桌面安装包不能安全内置邮箱 SMTP 授权码；必须通过运行时配置的 HTTPS 邮件中继投递，收件地址和邮件凭据保存在中继端。

## 设计不变量

- 专业度评估必须位于正式 Tip 聊天入口内，并在模型回答前完成。
- 评估结果必须包含等级、规则评分、领域和可解释原因，并写入本轮技能记录。
- 判为专业的问题必须强制执行联网研究；模型不能选择绕过。
- 专业问题未配置模型或联网搜索时必须明确阻断，不得静默退回演示回答或普通离线回答。
- 专业回答在联网和引用审查完成前不得流式展示或写入最终消息。
- 专业审查失败、审查异常或引用结构无效时，必须用明确的未通过结果替换原回答，不能只记录 warning。
- Tavily 免费额度模式仍最多消耗一次真实搜索；专业预检搜索必须计入本轮预算。
- 建议箱只向本机鉴权 API 提交；前端文案、DOM、请求体和响应均不得包含收件邮箱。
- 建议发送失败时保留用户输入并显示具体错误；成功后才清空。
- 建议接口必须限制长度、类别和频率，且不得携带文档、Tip、API Key 或系统 Prompt。
- 发布版邮件凭据不得打包进桌面应用。真实投递使用运行时配置的 HTTPS 中继，中继端固定目标邮箱。
- Electron 桌面模式不得读取开发者或打包环境中的模型 API fallback；“仅本地使用”只能读取当前设备用户主动保存在设置中的 API Key。
- `.env`、开发数据目录、测试 Key、邮件中继凭据和任何发布者 API Key 均不得进入安装包。

## 非目标

- 不把“包含术语”简单等同于高风险；高风险规则继续使用更严格的阻断门槛。
- 不声称规则评分是统计校准后的概率。
- 不在桌面应用中保存建议历史或邮件授权码。
- 不在当前 Windows 环境部署外部邮件中继或代替用户管理 QQ 邮箱授权凭据。

## 验收条件

1. 普通问法被判为非专业，明确的研究/工程/医学/法律/金融等专业问法被判为专业。
2. 只改变无关上下文不会把普通问题错误提升为专业问题。
3. 专业问题在联网未配置时正式阻断，且不会产生普通演示回答。
4. 专业问题在联网可用时，正式路径至少出现：专业评估 → 联网搜索 → 原文读取/交叉检查 → 回答 → 引用审查 → 专业审查结果 → 最终消息。
5. 模型尝试不调用搜索时，服务端预检仍真实调用搜索。
6. 审计返回 UNSUPPORTED、无引用、无效引用或审计调用失败时，原回答不会成为最终消息。
7. 普通问题不被强制联网，避免无谓消耗 Tavily 免费额度。
8. 建议不足最小长度、超长、未登录或频率过高时被拒绝。
9. 建议成功发送后，模拟中继收到经过限制的建议内容；请求体不包含目标邮箱。
10. 中继未配置或失败时前端保留输入，并明确提示未发送。
11. 中英文设置界面均显示建议箱，界面和构建产物的可见文本不显示目标邮箱。
12. focused tests、完整技能回归、Electron 烟测、安全审计和 Windows 打包态烟测通过。
13. 即使进程环境故意提供发布者 `OPENAI_API_KEY`，Electron 桌面模式中的新本地账户也不能调用它；安装包内容扫描不包含发布者密钥或开发数据。

## 发布配置缺口

当前尚未提供可部署的 HTTPS 邮件中继 URL。应用侧和模拟中继可以完成正式路径验证，但真实 QQ 邮箱到达性在配置并验证中继前标记为 `NOT_CAUSALLY_VERIFIED`。

## 2026-08-11 新鲜验证证据

- 先失败测试：在实现前，产品行为测试因 `assessQuestionProfessionalism` 不存在而失败；技能集成测试因正式聊天 trace 中没有 `professional_assessment` 而失败。
- focused 构建与测试：`tsc -b`、Vite 构建、服务端与 Python worker 构建全部通过。
- 产品行为测试：语言切换、退出登录、种子签名和专业程度评估均通过。
- 正式路径集成测试：服务端强制专业预检搜索；权威来源检查、引用审计和 `professional_review` 均进入同一聊天 run；不受支持的原始回答被替换，未进入最终持久化消息。
- 反事实测试：模型不主动调用搜索工具时，专业问题仍由服务端执行搜索；审计返回 `UNSUPPORTED` 时原回答不会成为最终输出；普通问题不会错误触发强制联网。
- API 隔离负向测试：测试进程故意注入发布者 `OPENAI_API_KEY`，Electron 桌面标记开启且新本地账户没有自己的 Key 时，正式聊天路径明确阻断，没有调用发布者 Key。
- 建议箱正式路径测试：已登录用户提交后到达模拟 HTTPS 中继；请求不包含收件地址；连续提交被限流；中继未配置时返回失败且界面保留输入。
- Electron 源码态烟测：本地入口、共享语言设置、建议失败保留、收件地址隐藏、Transformer 删除和退出登录清理均通过。
- Windows 解包应用烟测：`release/win-unpacked/AI Tip.exe --smoke-test --no-sandbox` 退出码为 0。
- `app.asar` 审计：共检查 56 个打包条目；没有 `.env`、`data` 或 `scripts` 路径；桌面隔离标记存在；发布者 API 回退在桌面模式返回空值；收件地址、测试哨兵 Key 和源码环境密钥均为零命中。
- 依赖审计：`pnpm audit --audit-level moderate` 未发现已知漏洞。

## 接入等级结论

- 专业程度评估：`LEVEL_5_PREDICTION_BEARING`。评估结果决定是否强制搜索、是否允许生成和是否需要审查，并可改变最终输出。
- 专业问题权威联网审查：`LEVEL_5_PREDICTION_BEARING`。服务端无法由模型绕过；搜索、来源权威性和引用审计失败都会阻止原回答成为最终消息。
- 桌面 API 隔离：`LEVEL_5_PREDICTION_BEARING`。正式桌面启动设置隔离标记，聊天入口真实读取该标记；反事实注入发布者 Key 后仍被阻断，打包内容审计无密钥。
- 建议箱到应用后端和模拟中继：`LEVEL_5_PREDICTION_BEARING`。设置界面提交进入鉴权后端并真实到达测试中继，失败、限流和隐私边界均已验证。
- 从生产中继到真实目标邮箱：`NOT_CAUSALLY_VERIFIED`。这是部署配置缺口，不得用模拟中继结果替代真实送达验收。

## 2026-08-11 第二轮审计：模型专业度判断与政策领域

### 审计纠正

1. 现有 `professional_assessment` 由服务端正则规则独立产生，模型没有参与专业度判断。此前结论只适用于“被规则命中的专业问题”，不能外推为通用模型专业度评估。
2. “法律与政策”虽然出现在领域名称中，但词表主要是诉讼、合同、行政法和合规术语；公共政策、政策工具、政策执行、政策评估、公共治理及主要政策分领域没有形成真实输入信号。
3. 规则漏判会令问题绕过专业预搜索、缓冲输出、引用审计和专业审查，因此属于同一个分类入口架构断点。
4. 单独让模型决定是否联网也不安全：模型误判、输出格式损坏或自定义 API 不兼容时，医学、法律、金融和政策问题可能被降级。规则必须保留为不可降级的安全下限。

### 新设计不变量

- 配置了模型 API 时，正式聊天入口必须在回答与搜索之前调用模型执行结构化专业度评估。
- 模型评估必须读取当前问题和有限选中文本，输出专业与否、等级、领域、判断置信度、是否要求联网审查及简短理由。
- 最终判定采用“模型提升 + 规则安全下限”：模型可以提升规则漏判的问题，但不能降低规则已识别的专业、高风险或政策敏感问题。
- 政策与公共治理必须成为独立领域，覆盖政策制定、政策工具、执行、评估、公共治理以及财政、产业、教育、就业、住房、人口、社会保障、卫生、环境、能源和数据治理等政策主题。
- 涉及现行政策、政策解释、政策比较、执行或效果的问题必须联网，优先使用政府、立法机关、监管机构、国际组织和正式研究机构的一手来源。
- 模型评估失败、无法解析或返回越界结构时，已配置模型的正式回答必须明确失败，不得静默使用旧普通回答路径。
- 模型未配置时只能显示规则预检来源；不得把规则判断标记成模型判断。
- 模型专业度评估不调用 Tavily，不消耗搜索额度；判定后的专业/政策预搜索继续计入本轮 Tavily 搜索预算，免费模式最多一次真实搜索。

### 新验收条件

1. 规则本来漏判、但模型判为专业的政策分析问题必须触发一次强制搜索，并经过权威来源、引用和专业审查后才能成为最终消息。
2. `professional_assessment` trace 必须明确区分模型评估与规则预检，记录模型领域、置信度和理由。
3. 模型将规则已识别的专业问题判为普通时，规则安全下限仍必须触发专业搜索。
4. 模型评估返回非 JSON 或非法字段时，回答必须被阻断；不得执行普通回答、演示回答或模型工具旧路径。
5. 政策问题的搜索结果必须至少包含可识别的权威来源，否则原回答不得成为最终消息。
6. 普通生活问题经模型判为非专业时不得触发 Tavily 请求。

### 第二轮新鲜验证证据

- 旧实现失败证据：政策样例被记录为“计算机与人工智能、规则 24/100、一般问题”，Tavily 搜索增量为 0，却生成了带 `[S1][S2]` 的最终回答；这直接证明旧路径可绕过证据链。
- 模型因果接入：集成测试中模型专业度评估实际调用 10 次；模型识别规则原本漏判的政策分析问题后，Tavily 搜索增量恰好为 1，随后通过权威来源、引用审计和专业审查才形成最终消息。
- 不可降级反事实：模拟模型故意把 RCU 专业问题判为一般，规则安全下限仍将最终等级保持为专业并强制联网。
- 失败阻断反事实：模型返回非 JSON 分类结果时，`professional_assessment` 为 error，最终消息明确报告专业程度评估失败，没有搜索，也没有进入普通回答、演示回答或旧工具路径。
- 额度负向测试：普通泡茶问题经模型判为一般后，Tavily 请求数保持不变；模型分类调用本身不消耗 Tavily。
- 政策规则测试：实质性政策工具/执行评估问题达到专业等级；即使简单现行政策问题尚未达到专业阈值，也被标记为必须联网审查。
- 政策权威来源：正式识别规则包含政府/教育科研域名以及联合国、UNDP、OECD、世界银行、IMF 和 ILO；打包产物中已验证这些规则存在。
- 完整回归：TypeScript、Vite、服务端和 worker 构建，产品行为、Python 数值、Python 沙箱、高级技能、正式路径集成及 Electron 源码态烟测均通过。
- Windows 1.5.1 打包态：解包应用烟测退出码 0；`app.asar` 包含模型分类器、政策领域和政策权威来源规则，不包含 `.env`、`data`、`scripts`、隐藏收件地址或测试发布者 Key。

### 第二轮接入等级

- 模型专业程度评估：`LEVEL_5_PREDICTION_BEARING`。模型结构化结果被正式聊天入口读取并能把规则漏判的问题提升为强制联网；删除或损坏结果会令正式回答明确失败。
- 政策与公共治理识别：`LEVEL_5_PREDICTION_BEARING`。政策分类决定预搜索、缓冲、引用审计和最终专业审查；政策样例的搜索与最终输出已通过反事实测试。
- 规则安全下限：`LEVEL_5_PREDICTION_BEARING`。模型降级输出不能绕过规则已识别的专业、高风险与政策敏感问题。
- 生产开放域分类准确率：尚无独立标注数据集评估，标记为 `NOT_CAUSALLY_VERIFIED` 的 `INDEPENDENT_EVALUATION` 缺口；当前证据证明正式路径和负向行为，不宣称分类器具有已校准的现实准确率。
