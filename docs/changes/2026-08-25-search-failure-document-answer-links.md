# 联网无结果时基于文档回答并提供百科检索入口

## 审计结论

当前正式链已经做到“搜索失败后保留非空回答”，但还没有完整满足“按文档内容回答并提供可点击百科入口”：

```text
搜索计划
→ Tavily 或备用参考站点没有取得结果
→ 无结果文本作为“联网证据”注入模型
→ 正确性规则又要求专业/政策主张只能由联网证据支持
→ 小模型可能把“外部事实不能核验”扩大成拒绝解释文档
→ 最终仅追加文字警告
→ 没有提供可继续检索的百科链接
→ 聊天正文中的裸 HTTPS 地址也不会渲染成超链接
```

已有上下文消息确实包含文档标题、选中原文和附近文本，达到 `LEVEL_3_CONSUMED`；但无结果分支没有明确要求模型继续使用这些字段，也没有从本轮搜索查询生成最终可点击入口，因此“无结果仍按文档回答”和“百科链接”尚未达到 `LEVEL_5_PREDICTION_BEARING`。

## 统一设计

1. 搜索没有取得有效证据时，模型仍必须回答用户问题；答案以本轮文档标题、选中原文、附近上下文和当前 Tip 对话为依据。
2. 必须明确区分：
   - “文档陈述/文档内解释”：可以依据用户提供的文档回答；
   - “已核验外部事实”：只有实际取得的联网证据才能支持。
3. 搜索失败不能触发拒答、删除原回答或用空消息结束；也不能把文档原文冒充已联网核验的事实。
4. 从本轮查询生成百度百科、360 百科、中文维基百科、English Wikipedia 和 Britannica 的人工继续检索入口。入口仅用于用户自行搜索，不计为已取得来源，不参与 `[S#]` 引用审计，也不宣称权威或最新。
5. 人工入口必须直接指向对应站点的公开搜索页，不经过开发者服务器，不消耗 Tavily 额度。
6. 聊天正文只把 `http://`、`https://` 裸地址渲染成外部链接；显示文本与持久化文本保持一致，不能破坏聊天 Tip 的字符偏移锚点。
7. Electron 继续使用既有外链策略：只允许 HTTP(S) 交给系统浏览器打开，应用内页面不导航到外部站点。

## 非目标

- 不把人工百科检索入口记作本轮搜索成功或权威来源。
- 不为某个问题、文档 ID 或测试标记硬编码答案。
- 不在 Tavily 失败后偷偷请求备用站点；人工链接不执行网络请求。
- 不降低医学、法律、金融、政策或其他专业问题的风险说明与人工复核要求。
- 不承诺百科内容一定准确、可访问、精细或最新。

## 先失败的回归与反事实验收

1. 让全部备用站点失败：最终回答必须包含当前文档原文形成的解释，不能包含拒答；必须包含至少一个中文百科和一个英文百科的公开 HTTPS 搜索入口。
2. 人工入口存在时，`web_search` trace 仍为 `warning`，有效证据数仍为零，回答不得出现伪造的 `[S1]`。
3. Tavily 返回 500：不请求备用站点，但仍按文档回答并提供百科人工入口。
4. 改变 AI 生成的中英文查询，人工入口的查询参数必须随之改变；不能复用旧查询或 stale cache。
5. 聊天正文 URL 检测只接受 HTTP(S)，拒绝 `javascript:` 等协议；去除链接包装后可见文本与原持久化文本完全一致，保证 Tip 偏移不漂移。
6. 搜索成功路径保持不变：真实来源继续使用 `[S#]` 与引用审计，人工入口不混入真实来源编号。

## 验收条件

- focused 产品、聊天正式链和嵌套 Tip 文本测试通过。
- `pnpm skills:test` 与 `pnpm desktop:smoke` 通过。
- 打包后的 Windows App 完成烟测；若本轮不重新打包，不得声称发布安装包已包含修复。
- 只有“本轮问题/文档上下文 → 搜索失败 → 文档型回答 → 本轮查询对应的百科入口 → 可点击渲染 → 消息持久化”可追溯，才可判为 `LEVEL_5_PREDICTION_BEARING`。

## 实施与验证结果

- 无结果证据消息现在明确要求模型继续读取同一轮文档标题、选中原文、附近上下文和 Tip 对话，并区分文档陈述与外部核验结论。
- 新增拒答恢复门：测试模型在全部站点失败后故意返回“无法回答”，正式聊天检测后执行 `SEARCH_FAILURE_DOCUMENT_RECOVERY_V1`，第二次回答真实消费选中原文“自注意力机制允许……”并替换拒答；若模型第二次仍拒答，确定性兜底会保留选中原文与附近上下文，而不是返回空白或纯拒答。
- 本轮 AI 生成的 `queryZh/queryEn` 进入五个百科公开搜索页 URL；只改变查询会改变链接。链接不经过应用服务器，不执行请求，不消耗 Tavily 额度。
- 全部备用站点失败和 Tavily 500 两条正式聊天路径均产生非空文档型回答、中英文百科入口和 `manual_lookup` warning；原 `web_search` trace 的来源仍为零，回答没有伪造 `[S1]`。
- 聊天正文只识别 HTTP(S) 裸地址，`javascript:` 保持普通文本；可见字符没有被增删，已有聊天 Tip 字符偏移保持不变。
- Electron 桌面烟测在真实消息 DOM 中验证了 `a[data-message-link]`、正确的百科 `href` 和 `target=_blank`；既有窗口策略会把 HTTP(S) 外链交给系统浏览器并阻止应用窗口外部导航。
- `pnpm skills:test` 全量通过；Supabase 日志中的两个 503 是既有故意注入的失败隔离负向测试，其最终断言通过。
- `pnpm desktop:smoke` 通过，包含 `clickableSearchLink=true`；PDF、OCR、Word 表格、递归 Tip、第一条 Tip 预览、长回答、登录凭据和本地模型回归继续通过。

## 接入等级

- 无结果搜索 → 文档上下文 → 拒答检测/恢复 → 最终持久化回答：`LEVEL_5_PREDICTION_BEARING`（受控正式聊天反事实）。
- 本轮双语查询 → 百科入口 URL → 最终消息 → Electron 可点击外链：`LEVEL_5_PREDICTION_BEARING`（查询反事实 + 打包桌面 DOM 烟测）。
- 百科入口仅为人工搜索便利，不是搜索证据、权威来源或独立事实评估；其内容质量仍为 `NOT_CAUSALLY_VERIFIED`，界面和回答均未将其误标为证据。
