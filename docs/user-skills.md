# Skill 管理使用说明

主页面左侧“管理”区域点击 **Skills · 技能**。阅读文档时，也可以从 **AI 设置 → Skill 管理** 打开同一个窗口。管理窗口覆盖在当前页面上，关闭后保留原编辑器与阅读位置。窄窗口在文档库右上角提供拼图图标入口。

## 导入和启用

1. 点击“导入文件”选择 `SKILL.md`、普通 `.md` 或一个 Skill 的 `.zip`；带参考资料的 Skill 也可以点击“导入文件夹”。管理窗口内支持拖入单个文件。
2. 检查右侧预览中的名称、用途、正文与参考资料，必要时修改。
3. 点击“添加 Skill”。此时只保存在本机，默认未启用。
4. 打开左侧开关。启用内容从下一次发送 Tip 问题起进入模型请求；正在生成的回答继续使用其开始时的版本。

左侧支持名称/描述搜索与全部/启用/未启用筛选。右侧可编辑指令和附带文本资料，保存按钮固定在详情区域底部。导出 ZIP 包含完整文本与资料，重新导入仍需手动启用。删除会确认；既有回答和它们的 Skill 版本记录保留。

聊天输入框的纸飞机旁新增 **Skills** 按钮。点开后每个 Skill 各有一个开关，可以只开启需要的几个；它与管理页使用同一份账户选择，不需要在两处重复配置。保存开关时暂时阻止发送，确保下一条问题使用已保存的选择。正在生成时不修改本轮快照。选择窗口也能直接打开管理页。

未保存修改时，关闭窗口、切换 Skill 或开始另一项导入会提示是否放弃。重名导入不会覆盖旧 Skill；如果其他窗口改过当前版本，保存会明确报冲突。

## 支持的格式

普通 Markdown 文件直接作为指令导入，名称初始取自文件名，也可以在应用中新建。标准 Skill 使用 YAML 元数据加 Markdown 正文：

```markdown
---
name: paper-reading
description: 阅读论文时，分析研究问题、实验设计、证据和结论边界。
---
先解释选中原文，然后区分作者的观察、假设和推断。
不要把相关性直接当作因果关系。
依据提供的文档说明实验比较、评价指标和适用范围。
文档未给出的信息要明确指出，不要自行补造。
```

参考资料可以放在 `references/` 或 `assets/` 等子目录，用相对链接引用，例如 `[阅读清单](references/checklist.md)`。导入时必须一起提供。支持 UTF-8 的 MD、TXT、JSON、CSV、YAML/YML 文本。

此版本实现 Agent Skills 格式中的指令与文本资料子集：不运行导入的脚本，不授予 Shell、外部程序或任意文件访问权限。需要脚本或二进制资源的包会明确拒绝，不显示成已兼容。

单次上传最多 2 MB，包内最多 64 个文件、每个文本最多 64 KB、每个 Skill 内容最多 48,000 字符；每个账户本机最多保存 30 个，同时启用最多 4 个，完整模型 Skill 上下文上限 64,000 字符。超限会报错，不悄悄截断。

## 数据和模型请求

Skills 按账户存储在应用本地数据目录的 `user-skills.json`，不会随“上传云端”操作自动上传到 Supabase。删除账户/清除本地账户数据时同步清理该账户的 Skills。

启用后，完整指令和附带文本会发送给当前选择的模型。使用在线模型时，这些内容也会发送给该模型提供方；使用本地模型时由本地接口处理。Skill 不能开启已关闭的联网搜索或其他工具。它是回答配置，不代表已执行某个脚本，也不等于事实正确性保证。

回答的折叠工具记录会标注“已载入 Skill 指令”，保留 Skill ID、版本和内容/状态摘要。摘要用于追溯本次实际配置；导入、编辑或重启不会把旧版本冒充当前版本。

## 开发验证

先生成当前客户端与本地服务构建：`pnpm desktop:prepare`，然后运行 `pnpm user-skills:test`。验证报告为 `docs/changes/verification/user-skills-latest.json`，绑定本轮源码与构建摘要、运行 ID、测试实际退出码及输出。

受控 HTTP 模型回归验证真实应用入口中的数据依赖和反事实输出，不代表真实模型在独立任务上的语义遵循性。后者为 `NOT_CAUSALLY_VERIFIED`。此轮 Windows Electron 验证不代替 macOS 真机或商店签名验收。

格式参考：[Agent Skills 官方规范](https://agentskills.io/specification)。
